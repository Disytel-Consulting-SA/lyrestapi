# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

REST API (Spring Boot 2.7.6 / Java 8) over the Libertya / OpenXpertya ERP. It runs as a
standalone container, connects directly to the ERP's PostgreSQL database, and delegates all
business logic to the Libertya core libraries (`OXP.jar`, `OXPXLib.jar` in `/ServidorOXP/lib/`).
It does *not* talk to a Libertya application server — it loads the ERP model classes in-process
and drives them against the DB.

## Build & run

```bash
./gradlew build                 # compile + run integration tests + build fat jar
./gradlew bootJar               # build jar only (build/libs/lyrestapi-1.0.0.jar)
./gradlew test                  # integration tests (needs a live Libertya DB — see below)
./gradlew test --tests 'org.libertya.api.InvoiceIntegrationTests'          # single class
./gradlew test --tests 'org.libertya.api.InvoiceIntegrationTests.someTest' # single method
```

Run the jar (JasperReports must be on the loader path — see "JasperReports" below):

```bash
java -Dloader.path=libs/JasperReports-ngroovy.jar -jar build/libs/lyrestapi-1.0.0.jar
```

Docker: `./DockerCreateImage.sh` (builds jar + image), `./DockerRunContainer.sh <DB_HOST> <DB_NAME>`.

Connection and behavior are configured via env vars consumed in `application.properties`
(`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`, `CLIENT_ID`, `SERVER_PORT`,
`TOKEN_SECRET`, ...). Swagger UI is served at `/swagger-ui`, OpenAPI at `/api-docs`,
actuator-style monitoring at `/monitor/**`.

## Architecture

### Request flow: Controller → (Service) → Repository → Libertya model

Every resource follows the same four-layer pattern. The simplest CRUD resources skip the
service layer entirely; only multi-part *documents* (invoices, orders, payments, etc.) have one.

- **stub/iface + stub/model** (`src/main/java/org/libertya/api/stub/`): **auto-generated, do not
  edit by hand.** `XxxApi` interfaces carry the `@RequestMapping` / Swagger annotations; `model`
  classes are the JSON DTOs. Generated by swagger-codegen from `src/main/resources/ly-rest-api.yaml`
  (which `$ref`s per-endpoint files under `resources/paths/` and per-entity schemas under
  `resources/model/`). Regenerate with `utils/genClasses.sh` (calls `utils/genSchema.sh` first,
  which builds the `model/*.yaml` schemas from live DB metadata via `genSchema.sql`).

- **controller** (`controller/`): implements the generated `XxxApi` interface, extends
  `AbstractController`. Methods are thin one-liners that delegate to one of the `AbstractController`
  helpers — `retrieveAction`, `retrieveAllAction`, `insertAction`, `updateAction`, `deleteAction`,
  `processAction` — passing a lambda. Each helper maps exceptions to HTTP status:
  `ModelException`→409, `AuthException`→401, `NotFoundException`→404.

- **service** (`service/`, only for documents): extends `AbstractService`. Wraps creation of a
  header + lines + taxes in a **single Libertya `Trx`** transaction. `AbstractService.create()`
  calls the subclass's `performCreate()`, optionally completes the document
  (`org.libertya.api.service.doc.complete=Y`), then commits — or rolls back on any exception.

- **repository** (`repository/`): extends `AbstractRepository`, which contains all the generic
  CRUD/process logic against Libertya `PO` model objects. A concrete repository is often just a
  constructor setting `tableName` and an `iface` factory, e.g.:
  ```java
  public InvoiceRepository() { tableName = X_C_Invoice.Table_Name; iface = Invoice::new; }
  ```
  `AbstractRepository` reflectively maps JSON fields ↔ `M_Column` metadata, applies defaults,
  resolves referenced values (`xxx_id__value` / `__detail` suffixes), paginates, and runs
  `DocAction` processing.

### Cross-cutting concerns

- **Security**: stateless JWT. `POST /token` (`SecurityController`) validates user/pass/client/org
  against the DB and returns a token; `JWTAuthorizationFilter` validates the `Authorization: Bearer`
  token on every other request and populates the Spring `SecurityContext`. Permitted-without-token
  paths (`/token`, `/api-docs/**`, `/swagger-ui/**`, `/monitor/**`) are whitelisted in
  `WebSecurityConfig`. The token's claims become a `UserInfo` (via `JWTUtils.infoOf(request)`)
  carrying the Libertya context (`Properties ctx` with client/org/user). `ClientOrgAuth` enforces
  that operations stay within the caller's client/org.

- **Libertya context**: `StartupLYService.init()` runs on `ApplicationReadyEvent` — it injects the
  DB connection into Libertya's `Ini`/`CConnection` and sets up the base `Env` context
  (`#AD_Client_ID`, `#AD_Language`, etc.). Per-request, the effective context comes from `UserInfo`,
  not the global `Env`.

- **Logging**: `EventLogAspect` (AspectJ `@Around` on all `controller.*` methods) logs every request
  and response line to the file in `logging.file.name`. Request/response truncation is configurable.

## JasperReports (invoice PDF printing)

`GET /v1.0/invoices/{id}/print` returns the invoice PDF as base64. Implemented in
`InvoiceService.printBase64()` → `generatePdfFromJasperProcess()`.

`/ServidorOXP/lib/JasperReports.jar` **cannot** go directly on Spring Boot's classpath (partial
Groovy classes trigger `GroovyBeanDefinitionReader`; the jar is signed). The workaround is a
stripped, unsigned copy at `libs/JasperReports-ngroovy.jar`, added as `compileOnly` and supplied at
runtime via `-Dloader.path`. To regenerate it if the original changes, and for the full printing
flow rationale (which AD_Process to pick, why not `MInvoice.createPDF()`), see the project memory at
`~/.claude/projects/-home-julian-libertya-git-lyrestapi/memory/` and `docs/invoice-print.md`.

## Integration tests

Tests under `src/test/java/org/libertya/api/` are `@SpringBootTest(RANDOM_PORT)` end-to-end tests
that hit the running app with `TestRestTemplate` and require a **live, pre-seeded Libertya QA
database** — they are not pure unit tests. `CommonIntegrationTests` documents the preconditions
(existing company 1010016 / org 1010053, `AdminLibertya` user, open accounting period for
`TEST_DATE`, `doc.complete=Y`). Many use hard-coded default IDs unless
`org.libertya.tests.use-dynamic-defaults=true`. `./gradlew build` runs them, so a build will fail
without a reachable configured DB.

## Adding a new entity/endpoint

1. Add the entity to `utils/genSchema.sh` and regenerate schema + stub classes with
   `utils/genClasses.sh` (or hand-write the `paths/*.yaml` + `model/*.yaml` and the `$ref`s in
   `ly-rest-api.yaml`), which produces `stub/iface/XxxApi` and `stub/model/Xxx`.
2. Create `XxxRepository extends AbstractRepository` (set `tableName` + `iface`).
3. Create `XxxController implements XxxApi extends AbstractController`, delegating to the
   `AbstractController` action helpers.
4. Only if it's a multi-part document needing transactional create/complete, add
   `XxxService extends AbstractService`.
